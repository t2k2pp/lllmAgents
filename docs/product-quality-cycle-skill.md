# 商品品質改善サイクルスキル設計

Status: implemented

## 目的

商品レベルを目指すレビューを単発の指摘で終わらせず、任意の観点について「レビュー → 修正・改善設計 → 実装 → 評価 → 記録」を再現可能にする。

## 呼び出し

組み込みスキル `product-quality-cycle` は、たとえば次の依頼で使用する。

> 信頼性の観点でレビュー、修整・改善の設計、実装・評価のサイクルを回して。

観点にはセキュリティ、UX、自律性、可観測性、性能、リリース品質、最近追加した機能などを指定できる。「商品レベル」のみの場合は、正しさ・安全性・運用性・UX・配布可能性を横断する。

## 既存スキルとの境界

- `code-review`: 指摘と修正案を返すレビュー専用
- `dev-workflow`: 範囲が明確な通常の実装・バグ修正
- `product-quality-cycle`: 設計・履歴・実行ログ・配布物まで調べ、改善を実装して前後評価と記録まで行う

## 安全条件

- 実行ログのプロンプトと応答は既定でレビュー文書へ転載しない。
- Windows で UTF-8 の設計書・スキルを PowerShell から読む場合は `Get-Content -Raw -Encoding UTF8` を使う。文字化けの兆候があれば内容を解釈せず、UTF-8を明示して再読込する。
- 未コミットのユーザー変更を変更・stageしない。
- commit、タグ、push は明示依頼がある場合だけ実施する。
- before タグは変更前 HEAD、after タグは全検証を通した commit を指す。

## 終了条件と継続

- サイクル番号は実装・評価のチェックポイントであり、引き渡し条件ではない。
- 1サイクルで完了しなければ、完了とは報告せず、残課題・理由・優先度・次サイクルの範囲と品質ゲートを明示して、そのまま次サイクルを実行する提案を行う。
- 「次サイクル候補」や「今回は選外」と記録するだけでは完了にならない。同じ依頼の観点・完了条件に含まれる実行可能な課題は、次のサイクルを直ちに開始して修正・評価まで続ける。
- 商品レベルを依頼された場合、レビューで発見した P0/P1 は同じ依頼の対象範囲に含む。修正済み、誤検出・重複と実証済み、外部条件または追加権限により blocked、ユーザーが明示的に受容、のいずれかになるまで完了扱いしない。
- P2/P3 も、当初の完了条件を満たすために必要なら継続して直す。残す場合は「将来対応」ではなく、当初範囲外である根拠、品質ゲートを妨げない証拠、または具体的 blocker を記録する。
- 新しい課題の発見が止まり、定義した品質ゲートを通り、未解決項目が上記の終端状態だけになった時点で引き渡す。

## 配布

スキル本体は `src/skills/builtin/product-quality-cycle/SKILL.md` に置く。`build:deploy` とインストーラーの既存 skill 配布経路により、他の組み込みスキルと同様に利用可能になる。
