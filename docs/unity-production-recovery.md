# Unity制作支援とコンテキスト復旧

Unity実制作で発生した問題を、道具の呼び方と制作判断に分けて改善する。
公式Unityスキルは操作仕様を扱い、builtin `unity-production` は原因診断、状態遷移・ライフサイクルのレビュー、証拠の扱い、制作記録からの再開を扱う。

## アプリの変更

- Unity bundle adapter v2: 登録済みMCPを先に確認し、CLI成功を利用条件にしない。`unity-production` へ誘導し、実行テスト保留と実装保留を混同しない。
- 階層要約: 空summary、不正なkeyFacts、出力打ち切りを採用しない。Layer 1はfinishReason・出力文字数・maxTokensと復旧コマンドを返す。入力超過と断定しない。JSON本文を診断に出さない。
- 引き継ぎ生成: 429は即座に伝播させ、再試行しない。出力打ち切りは見出しが揃っても拒否する。
- 履歴保存失敗・保存ID欠落ならリセットしない。アプリは手動/自動handoffとも別IDへ完全履歴を保存する。通常の自動保存で復元先を上書きしない。
- 引き継ぎ成功後は以前の階層要約をリセットし、次の圧縮で古い作業状態を再注入しない。

## 明示的なファイル引き継ぎ

```
/handoff from-file Development/HANDOFF.md
```

LLMの要約生成が失敗した場合、既存の制作メモを指定して再開できる。これはユーザーが選ぶモードであり、自動的に履歴を捨てる代替処理ではない。
メモはUTF-8の通常ファイル、64KB以下・16000文字以内。空メモは拒否する。空白を含むパスは引用符で囲める。
メモには目標、制約、実装済み、未実装、未確認、次に読むファイルを書く。元の履歴は表示された `/resume <id>` で復元できる。ToDo/Goalは現在の状態を維持する。

既存Unity bundleは不変であるため、新版を使うにはsetupで新しいbundleを生成し、その返却パスを起動指定へ反映する。builtin skillも配布/同期する。

## 検証方針

スキルPush → アプリPush → テストの依頼順序を守る。Push前は型と差分を確認する。
回帰テストはLLM呼び出し回数、429停止、保存失敗での履歴保持、無推論の引き継ぎ、出力打ち切りの拒否を確認する。
Push後に単一workerでユニット・E2E、パッケージとスキル読込、Unityの読み取り接続を確認する。ゲームの操作感を自動テスト成功とみなさない。
