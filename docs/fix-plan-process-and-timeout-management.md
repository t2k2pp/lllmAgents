# プロセス分離・タイムアウト刷新・対話デッドロック防止 設計書

## 1. 概要と背景

### 1.1 発生した障害
LLM Agent が `output/games/fantasy-voxel-world` を Git プッシュしようとした際、以下の障害が発生し、アプリ全体がユーザー入力を一切受け付けず完全停止した。

1. **対話入力待ちによるデッドロック**: `git push` が HTTPS 認証（Username/Password）を要求し、制御端末（`/dev/tty`）を直接開いて入力待ちになった。
2. **固定タイムアウトによる隠蔽**: 120秒の固定タイムアウトでシェル親プロセスのみが強制終了され、「認証待ちだった」という根本原因が Agent に伝わらず、孫プロセス（`git-remote-http`）が孤立して生き残った。
3. **TTY 入力競合による AskUser 完全停止**: 孤立した `git-remote-http` が `/dev/tty` で `read()` をブロックし続けたため、後続の `permission-manager` / `ask-user`（Inquirer）にユーザーのキー入力（Enter 等）が届かなくなった。

### 1.2 本質的な課題
- **課題 1（上流）: 非対話環境における対話要求の漏洩**
  - エージェントが実行するシェルは非対話であるべきだが、子プロセスが制御端末（`/dev/tty`）にアクセスできてしまい、対話入力待ちでハングする。
- **課題 2（中流）: タイムアウト設計の硬直性**
  - 一律 120 秒の固定タイムアウトは、正常な長時間タスク（ビルド、依存解決、巨大プッシュ等）を不当に殺す一方、出力がゼロのデッドロック状態でも無駄に 120 秒待たされる。
- **課題 3（下流）: プロセスライフサイクル管理の不備**
  - macOS/Linux で親プロセスのみに `kill()` を送っているため、孫プロセスがゾンビ化してリソース（TTY / ポート / ロック）を専有する。
- **課題 4（UI層）: 対話プロンプト（AskUser）の堅牢性**
  - TTY や stdin に外部要因で問題が生じた際、ユーザーが気付けず脱出不能になる。

## 2. 4層防御アーキテクチャ

```
┌───────────────────────────────────────────────────────────┐
│ Layer 1: 上流防御 (TTY 遮断 & 非対話 Fail-Fast)           │
│  - detached: true (POSIX setsid による制御端末 /dev/tty 切離し)│
│  - 非対話環境変数 (GIT_TERMINAL_PROMPT=0, CI=1 等) 常時注入 │
│  → 対話入力が必要なら 0.1 秒で即時エラー化し、Agent へ通知 │
└───────────────────────────┬───────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────┐
│ Layer 2: 中流制御 (アイドルタイムアウト & 長時間タスク許容) │
│  - 無通信監視 (stdout/stderr が出続けていれば制限なし継続)  │
│  - アイドルタイムアウト (無通信が N 秒続いたらハング判定) │
│  - 長時間タスクの定期進捗通知とユーザー確認 (継続/中断)     │
└───────────────────────────┬───────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────┐
│ Layer 3: 下流防御 (完全なプロセスグループ回収)            │
│  - POSIX: process.kill(-pid, 'SIGTERM' -> 'SIGKILL')      │
│  - Windows: taskkill /T /F                                │
│  → タイムアウト・中断・エラー時に孫プロセスも含め全滅させる  │
└───────────────────────────┬───────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────┐
│ Layer 4: UI層防御 (対話プロンプトの耐デッドロック)        │
│  - AskUser / PermissionManager での stdin 状態検証        │
│  - 強制脱出・SIGINT (Ctrl+C) の確実なハンドリング         │
└───────────────────────────────────────────────────────────┘
```

## 3. 詳細設計

### 3.1 Layer 1: TTY 遮断と非対話 Fail-Fast

#### (1) POSIX setsid（制御端末の切り離し）
- `spawn()` 時に `detached: true` を設定する。
- POSIX において `detached: true` は `setsid()` を呼び出すため、子プロセスは**新しいセッションリーダー**となり、親の制御端末（Controlling Terminal）から完全に切り離される。
- これにより、子プロセスやその孫プロセスが `open("/dev/tty", O_RDWR)` を試みても、OS カーネルが直ちに `ENXIO`（Device not configured）を返し、**ターミナルからの入力待ちになることが物理的に不可能**になる。

#### (2) 非対話環境変数の注入
`bash.ts` の `childEnv` に以下の環境変数をデフォルト注入する：
```ts
const NON_INTERACTIVE_ENV: NodeJS.ProcessEnv = {
  GIT_TERMINAL_PROMPT: "0",        // Git の対話プロンプト無効化
  CI: "1",                         // 各種 CLI ツールに CI モードを認識させる
  DEBIAN_FRONTEND: "noninteractive",
  NPM_CONFIG_YES: "true",          // npx 等のプロンプト抑止
  PIP_NO_INPUT: "1",               // pip の入力抑止
};
```
これにより、対話が必要なツールはミリ秒単位で `terminal prompts disabled` 等のエラーで終了し、Agent は即座に AskUser を通じてユーザーに判断を仰ぐことができる。

---

### 3.2 Layer 2: アイドルタイムアウト（無通信監視）と長時間タスク

#### (1) アイドルタイムアウトの仕様
- **従来の方式**: コマンド全体の実行時間が `timeout`（デフォルト120秒）を超えたら強制終了。
- **新しい方式**:
  - `idleTimeout`（デフォルト: 60,000ms = 1分）を新設。
  - `proc.stdout.on("data")` または `proc.stderr.on("data")` が呼ばれるたびに `lastActivityMs = Date.now()` を更新。
  - 最後の出力から `idleTimeout` の間、1バイトも出力がない場合のみ「ハング・無応答」と判定して終了させる。
  - `timeout`（ハードリミット）: 明示的に指定された場合のみ適用し、未指定（または 0）の場合は「出力がある限り無制限」を許容する（設定可能）。

#### (2) 長時間タスクの可視化
- 実行時間が 30 秒を超えるタスクについては、30 秒ごとに「実行中... (経過: X秒, 受信: Y bytes)」のハートビートログを出力する。
- ハングを検知した場合は、強制終了前に「どのようなコマンドが無応答になったか」の詳細な診断情報を結果に付与する。

---

### 3.3 Layer 3: 完全なプロセスグループ回収

#### (1) `killProcessTree` の刷新
- `detached: true` で起動されているため、子プロセスの PID はそのまま**プロセスグループ ID（PGID）**となる。
- POSIX では `process.kill(-pid, signal)` を呼び出すことで、親シェルだけでなく、子・孫・曾孫を含む**プロセスグループ全体にシグナルを一斉送信**できる。
- クリーンアップシーケンス：
  1. `process.kill(-pid, "SIGTERM")` を送信。
  2. 1秒待機してもプロセスグループが残っている場合、`process.kill(-pid, "SIGKILL")` で強制終了。
  3. Windows は従来通り `taskkill /T /F /PID <pid>` を使用。

---

### 3.4 Layer 4: AskUser / 対話プロンプトの堅牢化

- `withPrompt()` 実行時に、もし万が一 stdin が停止または異常状態にある場合でも、Ctrl+C を押せば即座にプロンプトを中断して安全に制御を戻せるようハンドラを保証する。
- TTY の排他制御が外れた際の stdin 復帰処理（`applyRawMode`）の安全性を再確認する。

## 4. 影響範囲とリスク分析

| 変更箇所 | 影響内容 | リスクと対策 |
|---|---|---|
| `src/tools/definitions/bash.ts` (`spawn`) | `detached: true` の追加 | 子プロセスがバックグラウンドセッションになるため、パイプの EOF 検出と終了監視を確実にする（`unref()` は呼ばない）。 |
| `src/tools/definitions/bash.ts` (`killProcessTree`) | `-pid` によるプロセスグループ kill | 他の無関係なプロセスを巻き込まないよう、`pid > 1` かつ自身と異なることを厳格にバリデーションする。 |
| `src/tools/definitions/bash.ts` (タイムアウト) | アイドルタイムアウト化 | 出力を全く出さずに長時間計算するコマンド（例: `sleep 100`）がアイドルタイムアウトで切れる可能性がある。→ パラメータで `idleTimeout` / `timeout` を明示指定できるようにする。 |
