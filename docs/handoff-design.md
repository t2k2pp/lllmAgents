# /handoff (引き継ぎメモを残してリセット) 設計書

> **ステータス**: implemented
> **作成日**: 2026-10-25 (docs 整理。 それまでメモの形の正本だった `docs/archive/context-strategy.md` §2.2 と、 実装 `src/agent/handoff.ts` / `src/cli/commands/handoff.ts` から書き起こした)
> **関連**: `docs/context-reduction-redesign.md` §7 (自動の整理とは別の、 手動のリセット)

---

## 1. 目的

「次にやることを残して、 一度コンテキストを空にする」 を利用者が決めたときに行う。
自動の整理 (`docs/context-reduction-redesign.md`) は履歴を残したまま減らすが、 `/handoff` は履歴を全部消して引き継ぎメモだけで続ける。
区切りでの自動リセットは廃止したので、 リセットはこのコマンドだけで行う。 引き継ぎ無しで消すときは `/clear`。

## 2. コマンド

| 書き方 | 動作 |
|---|---|
| `/handoff` | 引き継ぎメモを LLM に書かせ、 保存してからリセットする |
| `/handoff dry` | メモを作って表示するだけ (リセットしない) |
| `/handoff from-file <path>` | 保存済みのメモ (64KB 以下の UTF-8。 本文 1〜16,000 文字) を使い、 LLM を呼ばずにリセットする |

## 3. 手順

1. 引き継ぎメモを作る (`from-file` ならファイルの内容)
2. 今のセッションを保存し、 そのセッション ID を表示する (`/resume <id>` でリセット前の完全な履歴に戻れる)
3. 履歴を消す (`history.clear()`)
4. メモを最初の user メッセージとして入れる (先頭に `[引き継ぎメモ]`、 保存したセッション ID を併記)
5. メモを利用者にも全文表示する

**約束**: メモの生成と保存の両方に成功してから消す。 どちらかに失敗したら履歴には触れず、 理由を表示する
(履歴だけ消えてメモが無い状態を作らない)。 失敗時は `/handoff from-file <path>` での再開を案内する。

## 4. メモの形 (テンプレート固定)

```markdown
## これまでにやったこと
- (完了した作業を箇条書き。 結論のみ)

## 次にやること
- (未完了のタスク。 最初に着手すべきものを先頭に)

## 守るべき制約・決定事項
- (ユーザーが出した指示、 議論して決まった方針。 原文に近い形で)

## 関係するファイル
- path — 何のためのファイルか
```

「守るべき制約・決定事項」 を独立した節にするのが要点。 履歴が完全に消えるので、 ここが唯一の拠り所になる。

## 5. 生成の詳細 (`src/agent/handoff.ts`)

| 項目 | 値・動作 |
|---|---|
| 呼び出し | 脇の呼び出し `sideCall("handoff", …)` (`side_call` として記録)。 思考は残す (思考ありの方が直前の作業と数値を拾う) |
| 温度 / 出力上限 | 0.2 / 8,000 トークン (思考 + 本文の合算。 暴走を止める上限) |
| 渡す会話 | 会話の要約版。 1 メッセージ 600 文字 (ツール結果は 200 文字) まで、 全体 24,000 文字まで。 超えた分は古い側から落とし、 落とした件数を先頭に書く |
| 受理の条件 | 40 文字以上、 かつテンプレートの見出しが 2 つ以上ある。 出力上限で切れた (`finishReason=length`) ものは受理しない |
| 再試行 | 受理できなければ 1 回だけ再試行。 レート制限は再試行せずそのまま伝える |
