# 逐次実行とレート制限時の停止

2026-09-13のUnity制作中、Azureのレート制限が続く状況で、履歴555件の圧縮が56リクエストを同時送信していた。ツール実行上限とは独立した内部処理であり、プロンプトによる並列禁止では止まらなかった。

## 今回の修正

- ツール実行の既定上限を3から1へ変更。複数ツールも順番に実行し、停止結果が出たら残りは未実行として履歴に残す。
- 逐次モードではtaskのバックグラウンド委任も実行前に拒否し、同期委任を案内する。既に走っている別ジョブをこの設定変更だけで停止するものではない。
- Layer 1要約と意図/完了判定を逐次実行。途中失敗時は後続の要約を送信しない。
- 忘却選択のrate limitは再試行せず伝播し、hybridの要約へ進めない。
- Layer 2昇格のrate limitも停止させ、今回追加した要約ブロックを確定しない。
- ツール経由のrate limitはabortExecutionとして主ループを停止する。明示的並列モードでも停止検出後の待機ツールは起動しない。既に送信済みの並列リクエストを取り消す変更ではない。
- 並列実行の推奨は明示設定時だけ。localhostのポート違いを別マシン扱いせず、クラウド同士を独立した利用枠と推定しない。

## 既存設定と適用

既存のmaxParallelTools設定は勝手に上書きしない。起動中のアプリでは `/parallel 1` で保存できるが、内部要約の修正を反映するには更新版でアプリを再起動する必要がある。
ユーザーが明示的にリトライ/続行を選ぶ操作は、自動リトライと区別する。
同じマシン上の別プロセスや別アプリ全体を制御するグローバルな利用枠管理は今回の変更に含めない。

## 検証

モックproviderで56ブロックの最大同時送信数1、Layer 1/2の429後の停止と要約保持、忘却の再試行なし、実ToolExecutor経路の429後の未実行ツール記録を回帰テストにする。実Azureへの負荷試験は行わない。
