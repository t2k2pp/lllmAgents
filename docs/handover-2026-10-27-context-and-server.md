## 4. 進め方の約束 (前の引き継ぎ書から変わらない)

- タスクごとに Opus のサブエージェントを 1 つずつ使う (並列にしない)。 メインはオーケストレーションと結果の確認
- 各タスクで `npx tsc --noEmit` / `npm run lint` (エラー 0) / `npm run test:coverage` / `npm run test:e2e` を通し、 `npx biome format --write` してから
  main に直接コミット・push (ブランチを作らない、 `--no-verify` 禁止)。 コミット本文は `背景:` `変更:` `検証:` 必須
- 利用者の実データ (`~/.localllm`) はテストで触らない。 実機確認は一時ホーム (`USERPROFILE` / `HOME` を差し替え、 設定の写しを置く) で行う。
  写しでは Discord と chatLog を切る (利用者の Documents に書くため)
- 利用者の原則: 同じことをする複数のやり方を残さない。 フォールバック・黙った欠損をしない (失敗は見える形で)。 Claude Code に類似があればそれを参考にする
- 会話は日本語。 説明は平易に

## 5. 実機確認のこつ (前のチャットで分かったこと)

- パイプモードでは、 次の行が前の依頼の処理中に読み込まれて割り込みとして渡る。 依頼の間は十分に空け、 `/exit` は最後の応答が終わってから流す
- 記録: `~/.localllm/logs/sessions/<日時>_main.jsonl` の `request` / `response` (`tokensCached`)、 `reduction_event` / `reduction_skipped`、
  `cache_miss` (原因・比べた相手・ずれた位置)、 `side_call` (目的・指紋)
- サーバに直接聞くときは `/props`・`/slots`・`/apply-template` (組み立てたプロンプト) が使える。 チャットの呼び出しを送るときは、 利用者の作業が動いていないことを確かめる
