# 入力欄の ↑↓ 履歴の永続化

状態: implemented (2026-10-17)

## 1. 背景

入力欄で ↑↓ を押すと過去に打ったプロンプトを呼び出せるが、 履歴は `InteractiveInput` の
メモリ上にしか無かった。 そのためアプリを再起動して `--resume` / `--continue` / `/resume`
で会話を戻しても、 ↑ を押すと何も出てこなかった。

## 2. 方式 (Claude Code と同じ考え方)

Claude Code は `~/.claude/history.jsonl` に入力を作業フォルダ付きで追記し、 ↑↓ では同じ作業
フォルダで過去に打ったものを出す。 これに合わせる。

- 保存先: `~/.localllm/history.jsonl` (絶対パス。 `src/cli/prompt-history-store.ts`)
- 1 行 1 JSON: `{ "display": <入力そのまま>, "project": <作業フォルダの絶対パス>, "timestamp": <ms> }`
- 記録するもの: 入力欄で Enter により確定した空でない入力すべて (スラッシュコマンド、
  処理中の追加入力も含む)。 今までメモリ上の ↑↓ 履歴に積んでいたものと同じ範囲
- 読み込み: REPL 起動時に `process.cwd()` と同じ作業フォルダ (Windows は大文字小文字を
  区別しない) の行だけを古い順に読み、 新しい側 1000 件を ↑↓ 履歴の初期値にする
- 会話 session とは紐付けない。 resume したかどうかに関わらず、 同じ作業フォルダなら前回までの
  入力を呼び出せる

### 採らなかった案

- session ファイルに入力履歴を持たせる案: resume したときしか戻らず、 別 session で打った
  入力は呼び出せない。 Claude Code と使い勝手が揃わないため採らない (利用者判断)
- session の `messages` の user 発話から作る案: ハーネスが差し込む `[ハーネス] ...` 等も
  user 発話として保存されているため、 打っていない文が履歴に混ざる

## 3. 責務の分担

| 部品 | 役割 |
|------|------|
| `prompt-history-store.ts` | ファイルの読み書きだけ。 作業フォルダでの絞り込みと件数上限 |
| `InteractiveInput` | `initialHistory` を ↑↓ 履歴の初期値にし、 確定時に `onHistoryAdd` を呼ぶ。 ファイルは知らない |
| `REPL.createPromptHistoryOptions()` | 両者をつなぎ、 失敗を利用者へ知らせる |

## 4. 失敗時の扱い (黙って捨てない)

- JSON として読めない行・形が違う行: 読み飛ばし、 起動時に行数を警告表示する
- ファイルが読めない: 警告表示して空の履歴で起動する
- 追記に失敗: 初回だけ「次回起動では呼び出せない」旨を警告表示する (入力自体は処理を続ける)

## 5. 制限

- ファイルは削らないので使うほど伸びる。 読み込むのは新しい側 1000 件だけ
- 複数のアプリを同じ作業フォルダで同時に動かした場合、 起動後に他方で打った入力は
  再起動するまで ↑↓ に出ない (Claude Code と同じ)
- 非TTY (パイプ) モードは ↑↓ 履歴を使わないので記録もしない
