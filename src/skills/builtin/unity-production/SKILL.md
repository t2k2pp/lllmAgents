# Unity制作を進める

このスキルは「使うコマンド」ではなく「結果を判断して次の作業を選ぶ」ためのもの。対象プロジェクトの指示とユーザーの制作目標を最初に読む。公式Unityスキルがロード済みなら併用し、特定のゲーム名・アセット名・OS・モデルを前提にしない。

## 制作の進め方

1. **成果を定義する。** ユーザーの要求を、作る要素・守る既存資産・引き渡す場面に分けて短く記録する。入力/見た目/進行の未実装を、後で「未検証」と言い換えない。
2. **接続先と現物を実測する。** 登録済みUnity MCPがあれば直接、開いているsceneのpath/loaded/dirtyを取得する。Bash内のCLI疎通をMCPの前提条件にしない。対象不明のまま編集しない。
3. **小さく診断し、まとめて作る。** 必要な階層・bounds・参照だけを取得する。大量の階層全文や同じログを繰り返し文脈へ積まない。十分な情報があればコード・データ・シーンへ反映し、調査報告だけで終わらない。
4. **変更結果を追う。** 書いたコードではなく、Editorが読み込んだ型・値・参照・生成物を確認する。コンパイル完了、状態の入口から出口、生成と破棄の順序をそれぞれ見る。
5. **制作成果で区切る。** ユーザーが制作を優先している場合、入力の自動操作不能は手動確認待ちとして記録し、独立した素材・演出・HUD・進行の制作を続ける。細かなクリック依頼を何度も行わない。Computer Useの整備は依頼された別作業として扱う。

## 必要な参照だけ読む

- 接続/ツール/eval/アセット検索が失敗した → [references/diagnosis.md](references/diagnosis.md)
- コンパイル成功後の動作不備、配置、ポーズ、状態遷移を実装・レビューする → [references/production-review.md](references/production-review.md)
- 画像証拠、確認レベル、終了条件を決める → [references/evidence.md](references/evidence.md)
- 長い制作、モデルエラー、履歴整理失敗、再起動から再開する → [references/recovery.md](references/recovery.md)

参照パスはこのSKILL.mdのあるディレクトリを基準にfile_readで読む。ツール名の接頭辞・引数・利用可能機能は現在の登録schemaで確認する。

## この制作で守る境界

- 元scene・購入アセットを保持し、独自コード/材質/prefab/sceneに変更を集める。既存の未保存編集を勝手に破棄しない。
- 同じ実行基盤では逐次処理。レート制限を検出したら後続のLLM/画像解析/再試行を止め、実測エラーと保存済み成果を報告する。
- 診断用に状態を設定して描画を見ることと、実入力でゲームが成立したことを区別する。検証結果を作るためにHP/命中処理を直接書き換えない。
- 外部機能が使えない場合、その事実を隠す代替動作を入れない。制作内の試作表現は、ユーザーが認めた範囲で「試作」と明示して作る。
