# 証拠と引き渡し

## 確認レベルを混ぜない

| 証拠 | 言えること | 言えないこと |
|---|---|---|
| 再コンパイル完了、失敗なし | C#がコンパイルできる | ゲームが遊べる |
| runtimeのstate/HP/敵数 | その時点の値 | 入力と変化の因果、敵が見えた |
| frustum/Linecast/Collider | 視野・射線・衝突の条件 | 操作感、手動命中 |
| 保存された画像 | そのpathに画像がある | 目視済み |
| 実際に見た画像 | そのフレームで見えたもの | 操作や時間変化の成立 |
| 実入力の直前/直後値 | その操作で確認できた変化 | 未実行ルートや全ゲームの完走 |

画像pathは要求値ではなくツールの返却値を使い、ファイルの存在を確認する。`source=camera`はScreen Space OverlayのHUDを含まないことがある。`source=screen`は合成画面だが、Pause/非フォーカス時は古いフレームの可能性がある。runtime stateとHUDが違えば新しい描画証拠としない。

成果画像は再起動で消えるTempを避け、ユーザーが見られるproject内の開発記録へ保存する。画像解析不能なら未確認とし、存在しない画像を報告へ残さない。

## 完成判定

依頼された各要素を次の3列で管理する:

- **実装済み**: 使用されるコード/scene/dataまで接続している。
- **実装済み・未検証**: 未実施の確認方法を具体的に示す。
- **未実装/阻害要因**: 何が欠けるか、制作で解決可能か、外部入力が必要か。

「入力操作はユーザープレイへ任せる」は、Tポーズ、材質、画面遷移、音など依頼された制作を省略する理由ではない。逆に、入力自動化がないことを理由にユーザーへ延々と操作試験を依頼しない。

最終報告は成果scene、開始方法、短い操作説明、確認済みの証拠、残る試作表現/未確認を書く。Play速度やHPを診断用に変えた場合は記録し、終了時に復元する。実行中Playを引き継ぐ場合以外は停止状態を確認する。
