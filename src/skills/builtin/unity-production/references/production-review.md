# 「コンパイルが通った」の次に見るもの

全部を毎回検査するチェックリストではない。変更した機能と、その入力・状態・表示・寿命に関係する項目を読む。

## 配置と命中

- 配列件数やnonnullだけで配置が完成したと判定しない。ゼロ座標のままの要素、重複位置、カメラと同位置、カメラ背後を調べる。
- 敵の胸元などの注視対象を`Camera.WorldToViewportPoint`で確認する。z>0とx/yが0〜1内なら視野内の候補。描画成功とは別。
- `Physics.Linecast`でカメラから対象への遮断を確認。実インスタンスのCollider中心へRaycastし、最初のhitが敵か建物かを確認する。Colliderの件数だけでは命中を保証しない。
- 地表はRaycastとモデルboundsから決める。Yが負なら0.9へ直す、といった一律補正は地形上の配置を壊す。
- 街全体boundsは遠景・巨大な背景meshを含む場合がある。移動/敵配置は道路・建物の局所boundsで決める。
- Collider追加は対象sceneを確認し、既存Colliderとmeshの有無を調べて再実行で重複させない。元の購入FBXや全projectへ一括変更しない。

## 状態遷移

具体的な状態の例を紙上で追う: 開始→移動→到着→敵生成→射撃→全滅→次区間→終端→再開。

- Updateの早期returnより後に射撃があり、敵がいる間入力へ到達しない構造になっていないか。
- リロードや移動中に入力を制限しても、武器やHUDの演出更新まで止めていないか。
- 到着時に露出位置・cover位置・lookAtを更新しているか。移動前の露出位置へ毎フレーム戻していないか。
- 選択ルートは開始境界で固定。キーを保持中だけ参照するデータを切り替えると現在の敵・区間と不整合になる。
- 防御は要求開始と到達を区別する。復帰も固定の露出位置を基準にし、反復で位置をずらさない。

## 生成と破棄

呼び出し順序を読む。たとえば`SpawnCover → SpawnEnemies → DestroyEnemies`で、最後の関数がcoverまで消していないか。

- 敵のみの破棄、遭遇全体の破棄、ゲーム全体のリセットを区別する。
- 死亡は見た目を消すだけでは足りない。攻撃予約、Update、当たり判定を止める。
- 再開時に敵・HP・弾・時間/リロード・cover・移動進捗・フラッシュ・Invoke/Coroutine・表示を初期化する。
- Runtime作成のMaterial/AudioClip等の所有者と破棄を決める。リトライで増え続けないようにする。

## 素材と演出

- FBXを読み込めること、材質参照があること、URPで意図どおり描画できることは別。埋込material/texture/animationを調べ、独自の材質やprefabへ接続する。
- 色を乗せただけなら「テクスチャを復元した」と報告しない。通常敵とボスの差を見て分かるようにする。
- ボーン名は実物を確認する。名前に`l`を含むという条件はforearm等にも誤反応する。
- ポーズは初期localRotationを保存し、毎フレーム「基準姿勢×有限オフセット」から作る。現在回転へ毎フレーム掛け続けない。
- 照準位置と射撃レイの入力位置を同じ値にする。CanvasScaler・画面外pointer・フォント未対応文字も考慮する。図形照準はフォント依存を避けられる。
- 攻撃予告のboolを作るだけで終えず、実際の表示へ接続する。音・反動・リロード・命中の表示も使用箇所まで確認する。
