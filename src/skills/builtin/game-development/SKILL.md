# Game Development Skill

## 絶対ルール

### ✅ 品質基準
- **実際に動作するコード**を書く（擬似コード・スケルトンは禁止）
- ゲームループ・入力処理・描画処理を完全実装する
- エラーハンドリングを適切に含める
- コードにコメントを適切に付ける（日本語可）

### ❌ 禁止事項
- `// TODO: implement` などの未実装部分を残す
- 「あとは自分で実装してください」で終わらせる
- インポートエラーが起きるコードを書く
- **配列インデックスに浮動小数点を使う**（必ず `Math.floor()` でラップする）
  - ❌ `world[x][rows * 0.6]` → `undefined` → `NaN` 連鎖でゲーム全体が描画されなくなる
  - ✅ `world[x][Math.floor(rows * 0.6)]`
- **初期値にNaNが混入するコード**（全座標・サイズ計算に整数チェックを徹底）

## How It Works

### Step 1: 要件整理
実装すべき機能リストを確認：
- コア機能（最低限動くもの）
- 追加機能（あれば）

### Step 2: 単一HTMLファイルで実装（Webゲームの場合）
HTML+CSS+JavaScriptをすべて1つの `index.html` にまとめる。
外部ライブラリは CDN 経由で使用可能（ただし必須ではない）。

**必須実装要素：**
- ゲームループ（requestAnimationFrame）
- 入力処理（keyboard / mouse events）
- 描画（Canvas または DOM）
- ゲーム状態管理（start / playing / game-over）

### Step 3: 動作確認コメント
ファイル冒頭に以下を記載：
```
<!--
  [ゲーム名]
  操作方法：
  - [操作1]
  - [操作2]
  ブラウザで index.html を開いてプレイできます。
-->
```

### Step 4: 保存
`file_write` で `output/[ゲーム名]/index.html` に保存。

### Step 5: スモークゲート（ブラウザ成果物は必須）
保存したら、**`done` と宣言する前に** `game_smoke` ツールで最低限の動作を機械確認する。

- 呼び出し: `game_smoke({ path: "<index.html の絶対パス>" })`
- **PASS するまで「完成」「動きます」と言わない。** FAIL の主な原因と対処:
  - 未捕捉例外（例: `THREE.MathUtils.lerpAngle is not a function` のような存在しない API）→ 該当行を修正して再スモーク
  - console error → 原因を潰してから再スモーク
  - canvas が空（真っ黒/単色）→ 描画ループ・初期座標・NaN 混入を点検
  - 入力後フリーズ（画面が変化しない）→ 入力処理・ゲームループ・開始遷移を点検
- **スモークが見るのは「破滅的に壊れていないか」だけ**。操作感・ゲームバランス・面白さは判定しないので、最終的な手触りは人間の試遊で確認してもらう。
- **対象外**: 動きの少ない CLI/ターン制ゲーム（将棋・トランプ等）はスモーク不要。アニメーション/リアルタイム入力のあるブラウザゲームに適用する。

## ゲーム別実装ガイド

### 2Dマインクラフト風ゲーム

**MVPのコアループ（サバイバル簡易版）:**
```
ブロックを掘って資材を集める
→ 壁・屋根を建てて家を守る
→ 夜になるとスライムが出現・攻撃してくる
→ 朝になるとスライムが消える
→ より深く掘ってより頑丈な素材を集める
```
この「掘る→建てる→生き残る」の3ステップが1サイクル。プレイヤーが自分で目標を作れる最小構成。

**必須実装要素:**
- Canvas タイルベース描画
- プレイヤー（WASD移動・スペースでジャンプ・重力あり）
- ブロック種別（空気・土・草・石・木・葉 最低6種）
- マウス左クリック：ブロック破壊 → インベントリに追加
- マウス右クリック：所持ブロックを設置（インベントリから消費）
- インベントリ（所持数表示・無限設置禁止）
- HPバー（スライムに当たるとダメージ）
- 昼夜サイクル（空の色が変化・夜は暗くなる）
- スライム1種（夜に出現・プレイヤーに向かってホップ移動・接触ダメージ）
- HP0でゲームオーバー画面

## 完了条件
- ブラウザで `index.html` を開いて即プレイ可能
- 最低限のゲームループが動作している
- **ブラウザ成果物は `game_smoke` が PASS している**（Step 5）
- README.md にプレイ方法が記載されている

## 版管理（壊れても戻せるように）
ゲーム作成は「直って別が壊れる」回帰が起きやすい。**着手時に安全網を張る**こと。

- **チェックポイント機能（`/checkpoint`）が無効なら、作成開始時に `/checkpoint on` をユーザーに提案する。** 有効化すると、ファイル変更のたびにハーネスが裏で自動スナップショットを取り、いつでも直前の版へ戻せる（リモート不要・モデルの操作不要）。
- **回帰したと感じたら（前は動いていたのに壊れた／`game_smoke` が PASS→FAIL に転じた）、闇雲に前進修正を重ねない。** `/checkpoint list` で直前の動く版を確認し、`/checkpoint restore <n>` で戻すことをユーザーに提案する（実際の復元はユーザーが実行）。
- チェックポイントを使わない場合は、本物の Git で「動く版」の節目コミットを提案してもよい。
