# Business Book Writing Skill

## 絶対ルール（必ず守ること）

### ❌ 禁止事項
- **箇条書き（・、-、*、番号リスト）は章本文での使用を禁止**。本文はすべて散文（文章）で書く。
- 見出しだけで本文がないセクションを作らない
- キーワードの羅列・体言止めの連続で終わらせない
- 短文の連打（「〜です。〜です。〜です。」の5回以上の連続）を避ける
- 「以下に示します」「次のとおりです」と言ってから箇条書きにする構成

### ✅ 必須事項
- **散文（プローズ）で書く**：各段落は3文以上の連続した文章で構成する
- **語りかける文体**：「あなたの会社でも…」「多くのビジネスパーソンが…」のように読者に直接語りかける
- **具体的な事例やエピソード**を盛り込む（架空の企業・人物でも可）
- **段落間の論理的なつながり**：「しかし」「そのため」「こうした背景から」などの接続を使い流れを作る
- **各章2000字以上**の本文（目安）

## 文体ガイドライン

### ❌ 悪い例（箇条書き調・禁止）
```
## AI導入のメリット
- 業務効率化
- コスト削減
- 競争力強化
社内にAIを導入することで上記のメリットがあります。
```

### ✅ 良い例（散文・推奨）
```
生成AIを社内に導入した企業が口をそろえて言うのは、「最初の一週間で仕事のやり方が変わった」
という実感だ。単純な資料作成や議事録の整理といった作業が自動化されることで、社員は本来
やるべき創造的な仕事に集中できるようになる。ある製造業の人事部長はこう語った。「AIを使い
始めて三ヶ月で、採用資料の作成時間が七割減りました。その分、候補者との対話に時間を使える
ようになって、採用の質が上がったんです」。このような変化は、一企業の特例ではない。
全国の中堅・中小企業でも、同様の変革が静かに、しかし確実に進んでいる。
```

## How It Works

### Step 1: 目次（toc.md）の作成
`file_write` でまず目次だけ作成する。
- 各章のタイトルと200字程度の概要（文章で）を記載
- ファイル: `output/book/v[バージョン番号]/toc.md`

### Step 2: はじめに（00-はじめに.md）の執筆
- なぜこの本を書いたか（著者の動機・問題意識）
- 読者はどんな悩みを抱えているか
- この本を読むと何が変わるか
- 散文のみで1000字以上

### Step 3: 第1章の執筆
- 章の冒頭：具体的な場面・エピソードから入る（「ある日、〜部長は会議室で…」など）
- 本論：テーマを深掘り。事例・背景・分析を散文で展開（1500字以上）
- 締め：次章への橋渡しを文章でつなぐ

### Step 4: 自己品質チェック（書いた後に必ず実行）
以下を確認し、問題があれば書き直してから保存する：

```
□ 箇条書きが本文に使われていないか？（目次・手順以外で使ったら書き直す）
□ 段落あたり3文以上あるか？
□ 具体的なエピソード・事例が1つ以上あるか？
□ 「しかし」「そのため」「こうして」などの接続詞で段落がつながっているか？
□ 各ファイルが2000字以上あるか？（wc -mで確認するか、目安として確認）
□ 読者に語りかける表現があるか？
```

問題があれば書き直す。OKなら保存する。

## ファイル保存規則
バージョン管理で品質改善を追跡できるようにする：
- ディレクトリ: `output/book/v[番号]/`（例: v1, v2, v3...）
- 目次: `output/book/v[番号]/toc.md`
- はじめに: `output/book/v[番号]/00-はじめに.md`
- 第1章: `output/book/v[番号]/01-第1章-[タイトル].md`

## 完了条件
- 全章（最低5章以上）が散文形式で完成している
- 各章2000字以上
- toc.mdに全章のタイトル・概要が記載されている
- すべてのファイルが自己品質チェック済み
