# Code Review

## レビュー手順
1. **対象の把握**: file_read / glob / grep で変更されたファイルと影響範囲を確認
2. **重要度分類**: 発見した問題を Critical > High > Medium > Low に分類
3. **具体的な指摘**: ファイルパスと行番号を明記し、修正案を提示

## 観点
- **正確性**: ロジックエラー、境界条件、null/undefined の未処理
- **セキュリティ**: インジェクション、認証漏れ、機密情報の露出
- **パフォーマンス**: N+1クエリ、不要なループ、メモリリーク
- **保守性**: 命名、責務の分離、重複コード
- **テスト**: テストカバレッジ、エッジケース

## 出力フォーマット
```
### [Critical/High/Medium/Low] 問題のタイトル
- ファイル: `path/to/file.ts:42`
- 問題: 何が問題か
- 修正案: 具体的な修正コードまたは方針
```

## Rules
- 問題の指摘だけでなく、必ず修正案を添える
- 重要度が高い順に報告する
- 「問題なし」の場合も良い点を1-2個挙げる
