# コードレビュー観点 (共通リファレンス)

> ID-039 (2026-05-01): code-review (skill) / pr-review (skill) / code-reviewer (agent)
> の 3 ファイルが独自に重複していた観点リストを 1 箇所に集約したもの。
> 各エントリーポイントは本ファイルを参照すること。

## 重要度分類 (severity)

| ラベル | 内容 |
|--------|------|
| **Critical** | セキュリティ脆弱性 / データ損失 / 認証バイパス / 任意コード実行 |
| **High** | ロジックエラー / 重大なパフォーマンス問題 / 未処理エラー |
| **Medium** | コードスタイル / 保守性低下 / 重複 / 命名 |
| **Low** | マイナーな改善提案 / nitpick |

## チェック観点

### 正確性
- ロジックエラー / 境界条件の見落とし
- null / undefined / 空配列の未処理
- 非同期処理の race condition
- 状態遷移の漏れ

### セキュリティ (OWASP Top 10 を基準)
- インジェクション (SQL / コマンド / XSS / Path traversal)
- 認証・認可の漏れ
- 機密情報の露出 (API キー / token / 個人情報)
- CSRF / SSRF
- 安全でないデシリアライゼーション
- 古いライブラリ / 既知の脆弱性
- ロギング・監視の不足 (アクセスログ等)

### パフォーマンス
- N+1 クエリ
- 不要なループ / 全件走査
- メモリリーク (リスナー / タイマー / 循環参照)
- 同期 I/O のブロック

### 保守性
- 命名 (変数 / 関数 / クラス) の妥当性
- 責務の分離 (関数 / モジュール / レイヤ)
- 重複コード (DRY 違反)
- マジックナンバー / マジックストリング
- コメントが「何を」 ではなく「なぜ」 を説明しているか

### テスト
- カバレッジ (主要パス / エッジケース)
- 境界値テスト
- 異常系テスト
- テストの独立性 (順序依存・グローバル状態)

## 出力形式

```
### [Critical | High | Medium | Low] 問題タイトル
- ファイル: `path/to/file.ts:42`
- 問題: 何が問題か (具体的に)
- 修正案: 修正コードまたは方針

(必要に応じてコードブロックで例示)
```

## 報告のルール

- 問題の指摘だけでなく、 必ず修正案を添える
- 重要度が高い順に報告する
- 「問題なし」 の場合も良い点を 1-2 個挙げる
- 一度出した指摘を取り下げない (「まあ大丈夫だろう」 という甘い判定は禁止)
- ファイルパスと行番号を必ず明記する
