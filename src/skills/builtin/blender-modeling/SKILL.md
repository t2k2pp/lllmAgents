# Blender Modeling Skill

どんな物も「**調べる → 部品に分ける → 寸法の表 → 部品箱で組む → 撮る → 見て比べる → 表を直す**」で作る。手本の無い物でも、この順で作れる。
一度で良い形は出ない。**撮った絵を見ずに「できた」と言わない。**

このスキルのフォルダ（通常 `~/.localllm/skills/blender-modeling/`）:

| ファイル | 中身 |
|:--|:--|
| [references/bkit.py](references/bkit.py) | **部品箱**。断面をつなぐ・継ぎ目を溶かす・箱・円柱・押し出し・船体・屋根・穴・左右・並べる・揺らした塊・撮る・測る・書き出す・ローポリ・ボクセル |
| [references/examples/](references/examples/) | 部品箱の使い方の見本: `creatures.py`（馬・人）・`objects.py`（机・剣・家・車・船・江戸の町家）・`nature.py`（岩・木）。Blender 5.2 で動作確認済み |
| [references/proportions.md](references/proportions.md) | 寸法の目安（人・動物・家具・道具・乗り物・建物） |
| [references/styles.md](references/styles.md) | 様式の見分けどころ（江戸・昭和・今の家・ファンタジー・和と洋の城・乗り物） |
| [references/library.md](references/library.md) | **手本帳**: うまくできた物を残し、次の出発点にする決まり |

## 0. 最初に確かめる（毎回）

1. **道具**: `mcp__blender__*` の道具があるか。
   - ある → §6。最初に `mcp__blender__get_addon_status` と `mcp__blender__get_scene_info`。
   - 接続できない（connection refused）→ Blender が開いていない。開いて 15 秒待ってやり直す（Windows: `start "" "<blender.exe>"`。よくある場所 `C:\Program Files\Blender Foundation\Blender <版>\blender.exe`・`C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe`／macOS: `open -a Blender`）。
   - 無い → §7（画面無し）。報告の最後に「`localllm --install-blender` を実行して起動し直すと、起動中の Blender を直接操作できる」と伝える。
2. **目**: 小さな絵を 1 枚撮り、**`file_read` でその PNG を開いて自分で見る**（メインのモデルが画像を見られる設定なら、画像そのものが会話に載る）。`file_read` が「画像を見られない設定です」と返したら `vision_analyze` を使う。どちらも失敗したら形の良し悪しを判断できない。続けてよいが、ユーザーに「画像を読めるモデルを設定してほしい」と伝え、報告では「目で確かめていない」と書く。数値の確かめ（`measure`・`landmark_fraction`）は必ずやる。
3. **出力先**: ユーザーが言った作業フォルダ（無ければ聞く）。
4. **手本帳**: [references/library.md](references/library.md) の場所の `INDEX.md` に、同じ物か近い物があるか見る。あればそれから始める。
5. **見た目の様式**: 言われなければ **リアル寄り（なめらか・角は少し丸い）**。「ボクセル」「積み木」「ローポリ」「トゥーン」と言われた時だけ §5。

## 1. 調べて、部品に分ける（手本の無い物はここが大事）

1. **何か**をはっきりさせる: 時代・様式・大きさ・用途（ゲームの背景か、近くで見る主役か）。分からなければユーザーに聞く。参考の絵・写真があればもらう（`vision_analyze` で見て、形の特徴を言葉にする）。
2. **寸法**: [proportions.md](references/proportions.md) に無ければ `web_search` で実物の寸法を調べる（例「江戸 町家 間口 奥行き 寸法」「軽トラック 全長 全幅」）。出典を表に書く。
3. **見分けどころ**: 建物・乗り物は [styles.md](references/styles.md) から、無い様式は調べて、「それらしく見せる特徴」を 4〜6 個書く。
4. **部品に分ける**: 全体を 5〜20 個の部品に分け、部品ごとに「形の種類」と「道具」を決める:

| 形の種類 | 道具 | 例 |
|:--|:--|:--|
| なめらかな体・手足・首・尾 | `loft` を部位ごと → `fuse` → `paint_by_parts` | 人・動物・竜・魚・キャラ |
| 角のある板・柱・箱 | `box`（角は `add_bevel` で丸まる） | 壁・机・柱・瓦・格子 |
| 丸い棒・車輪・塔・樽 | `cylinder`（`radius_top=0` で円すい） | 車輪・柱・塔・煙突 |
| 正面か横から見た形が決め手 | `prism`（plane="XZ" 正面・"YZ" 横・"XY" 上） | 屋根の妻・剣の刃・車の横顔・看板 |
| 流れる胴 | `hull`（断面の形を自分で決める） | 船体・車体の丸み・飛行機の胴 |
| 屋根 | `gable_roof`（切妻）・`shed_roof`（片流れ・庇）。**板を自分で傾けない**（回す向きの符号を間違えやすい） | 家・町家・城の各層・小屋 |
| 穴・窓・戸口・切り欠き | `cut` | 窓・戸口・車輪の切り欠き・狭間 |
| くり返し・左右 | `repeat`・`mirror_x` | 格子・瓦・手すり・左右の脚 |
| 自然のでこぼこ | `blob`（`seed` を変える）・`tube` | 岩・葉の塊・茂み・枝 |

5. 道具が足りなければ、bkit の関数をまねて自分で書く（bpy・bmesh で）。
6. 形の種類が混ざる物（騎士と馬・家と庭・車と人）は、物ごとに作って最後に並べる。

## 2. やってはいけないこと（前に失敗した形）

- 生き物の体を Skin モディファイアや円柱・球の寄せ集めで作らない（棒をつないだ形になり、付け根が割れる）。
- 生き物の部位を別々の物のまま重ねて終わらない。必ず `fuse` で 1 枚の皮にする。
- 角のある物の角を尖ったままにしない（少し丸めると光が当たり本物らしく見える）。
- 寸法を当て推量しない。調べるか聞くかしてから表を書く。
- **別の動物の置き方のコードを写さない**（2026-11 狼: 猫の「光線で頭の表面を探して目を置く」コードを、猫用に決め打ちしたずらしの値ごと写し、狼の目があごの高さに付いた。置く道具はエラーを出さずに間違った所へ置く）。目・鼻・耳は、その動物の寸法の表から位置を決め、置いた後に `landmark_fraction` で数値を確かめる。
- **「何の動物に見えるか」が当たっただけで できた としない**。種類当ては顔のつくりの誤り（目の高さ・目と鼻の間・耳の位置）を見逃す。
- 長い 1 本のスクリプトを一度に書かない。作る → 撮る → 直すを小さく回す。
- ノードを名前で探さない（言語で名前が変わる）。`n.type == "BSDF_PRINCIPLED"` のように型で探す。
- `generate_3d`・`import_asset`・`search_assets`（外のサービス・有料・ライセンスあり）は、ユーザーが許した時だけ。
- 頼まれていない様式（ボクセル・ローポリ）にしない。
- 実在の商標・ロゴ・店名・実在の人の顔を作らない（看板の字は業種の言葉だけ）。
- Blender の版で API が違う。分からない所は小さなスクリプトで確かめてから使う。

## 3. 座標の決まり

単位 m・上 +Z・地面 z=0（足の裏・車輪の下・建物の床をそろえる）・前 -Y・右 +X。左右対称は片側を作って写す。
書き出す先の決まりがあれば合わせる（`export()` は Unity 向けの -Z 前・Y 上が既定）。

## 4. 作って確かめる

1. 作業フォルダに `<名前>.py` を書く。先頭で bkit を読み込む（[library.md](references/library.md) の「build.py の決まり」と同じ）。寸法は先頭に名前付きの定数で。
2. 作る → `measure(ob)` で寸法を表と比べる（5% 以内か・一番下が 0 か）。
3. `render_views(ob, <出力>, <名前>)` で 横・前・後ろ・上・斜め を撮る。生き物は加えて **`render_closeup(<出力>, <名前>, <頭の中心>, <頭の長さ×1.5>, view="side")` で頭の横の寄りを必ず撮る**（前から見た絵では、目の高さの誤りが見えない）。
4. **撮った PNG を `file_read` で開き、自分の目で見る**（下の問いを自分に向ける。会話の文脈＝寸法の表と照らせる）。画像を見られない設定のときだけ `vision_analyze` に具体的に聞く。答えから**表の数値**を直して 2 に戻る。
5. **顔の目印は数値でも確かめる**（目で見るだけにしない）。スクリプトの中で:
   ```python
   f = landmark_fraction(head_or_body, eye_location, band=0.01, z_min=<首より上の高さ>)
   check_range("目の高さ（頭の断面の割合）", f, 0.55, 0.8)   # 範囲は proportions.md の表から
   ```
   目・鼻先・耳の付け根それぞれについて、表の範囲を外れたら止まるようにする。範囲の外なら置き方を直す（置く道具の値を信じない）。
6. 5 回直しても良くならない所は、残った問題として報告に書く（ごまかさない）。
7. 形が決まったら細部（目・取っ手・縁取り・瓦の筋・看板）と色・材質（金属は `metallic=1`）。
8. 書き出す: `export()`。ゲームに使うなら `decimate` で面を減らす（目安: 小物 500〜2 千・家具 2 千・動物と人 1〜3 万・車 3 千〜1 万・建物 5 千〜2 万）。
9. ユーザーが良いと言ったら（または目と数値で確かめ終えたら）、**手本帳に残す**（[library.md](references/library.md)）。

### 見る時の問い（自分で見る時も vision_analyze に聞く時も）

一度に全部を確かめず、絵 1 枚に 3 つまで。「良いですか」ではなく、場所を挙げて確かめる。**種類当て（「何の動物に見えるか」）だけで終わらない**。

- 全体: 「〇〇の形・比率・部品の位置のうち、寸法の表と違う所はどこか」
- 生き物の頭（横の寄りの絵で）: 「(1) 目は頭の高さの何割の所にあるか（下端＝0）。表の範囲に入っているか (2) 目と鼻先の間は頭の長さの何割か (3) 耳の付け根は目より後ろ・上にあるか」
- 生き物の体: 「(1) 背の線・関節の位置と曲がる向きは自然か (2) 付け根に割れ目・めり込み・折れ目はどこか (3) 頭・首の大きさは体に比べて自然か」
- 角のある物: 「(1) 部品どうしに すき間・めり込み・浮き はあるか (2) 縦横の比率は実物らしいか (3) 角が尖りすぎて見える所はあるか」
- 様式: 「〇〇（江戸の町家など）らしさの見分けどころ（格子・虫籠窓・瓦…）のうち、見えている物・見えない物はどれか」
- 自然の物: 「(1) 整いすぎて作り物っぽくないか (2) 浮いていないか (3) 大きさの比は自然か」

## 5. 見た目の様式（頼まれた時だけ）

| 様式 | やり方 |
|:--|:--|
| リアル寄り（既定） | 見本のまま。なめらか・角は少し丸い |
| ローポリ | 形を作った後 `lowpoly(ob, 0.03〜0.2)`（面を減らして平らに塗る） |
| ボクセルアート（積み木） | 形を作った後 `ob = voxelize(ob, 積み木の大きさ)`（色は元の面から引き継ぐ。積み木は細い所の太さ以下に） |
| トゥーン | リアル寄りで作り、材質を単色・`roughness=1` |
| デフォルメ（2〜3 頭身） | 寸法の表で頭を大きく・手足を短く太く |

## 6. MCP で進める（起動中の Blender）

- 最初に 1 回、部品箱を読み込む: `execute_blender_code` で `exec(open(r"<スキルのフォルダ>/references/bkit.py", encoding="utf-8").read(), globals())`。以後は関数を呼ぶだけ。
- コードは**小分けに**送る（部品を作る・一体にする・色・撮る を別々に）。
- 見るのは `mcp__blender__look`（画面を撮る）か `render_views`・`render_closeup`。MCP の道具が返す絵は、メインのモデルが画像を見られる設定なら結果の後に添付される（自分で見る）。保存した PNG は `file_read` で開く。見られない設定のときだけ、その場所を `vision_analyze` に渡す。
- 区切りごとに保存: `bpy.ops.wm.save_as_mainfile(filepath=r"<作業フォルダ>\<名前>.blend")`。
- **ユーザーの開いている場面の物を消さない**（`clear_scene()` は使わない）。`get_scene_info` で中身を見て、新しい場面（`bpy.data.scenes.new`）かコレクションに作る。

## 7. 画面無しで進める（MCP が無い時）

- `"<blender.exe>" -b --python <スクリプト> -- <出力フォルダ> [種類]` で動かす。見本はそのまま動く。
- 失敗したら出力の `Traceback` と `Error` の行だけを読んで直す（全文を読まない）。

## 8. 報告

- 作った物の場所（`.blend`・`.fbx`・絵）、面の数、寸法（`measure` の結果）、寸法の出典。
- **確かめたこと**と**確かめていないこと**を分けて書く（絵を見られなかったら、そう書く）。
- 残った問題と、次に直すならどこか。手本帳に残したなら、その場所。
