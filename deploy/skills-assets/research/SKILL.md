# Research Workflow

## 調査手順
1. **理解**: file_read / grep / glob でコードを広く読み、構造を把握する
2. **検証**: 仮説を立てたら bash やツールで実際に確認する（推測で結論を出さない）
3. **文書化**: 調査結果を file_write でまとめる（依頼があれば）

## 調査テクニック
- **エントリポイントから辿る**: main/index → 依存先へ深掘り
- **grep で横断検索**: 関数名、型名、設定キーをプロジェクト全体で検索
- **git log で経緯を追う**: なぜそうなっているかは変更履歴に残っている
- **web_search / web_fetch**: 外部ドキュメント、ライブラリの仕様確認

## 報告フォーマット
- 調査対象と目的
- 発見した事実（ファイルパスと行番号を明記）
- 結論と推奨事項
- 不明点・要追加調査事項

## Rules
- 推測と事実を明確に区別する
- 「おそらく〜」で終わらせず、検証可能なものは検証する
- 調査途中でもメモを取る（ask_user で中間報告、または file_write で調査メモ）
