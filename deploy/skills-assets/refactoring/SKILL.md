# Refactoring

## 作業開始前の影響範囲調査
1. **grep で全参照を洗い出す**: 対象のクラス名・関数名・コマンド名・日本語名称で全ファイルを検索する
2. **対象範囲**: src だけでなく tests, docs, README, DESIGN, CLAUDE.md, config, package.json も含める
3. **grep 結果から修正計画を立てる**: 何ファイル・何箇所に影響があるか把握してから着手する

## 変更の実施
1. **依存される側から変更**: 型定義・インターフェース → 実装 → 呼び出し側 → テスト → ドキュメント
2. **削除は段階的に**: import 参照を外す → 使用箇所を修正 → ファイル/関数を削除
3. **中間状態でもビルドが通る**ように保つ（一度に全部壊さない）

## ドキュメントの同期
- コード変更と同じコミットで関連ドキュメントも更新する
- 対象: README.md, DESIGN.md, docs/ 配下の設計書, CLAUDE.md
- 新機能追加時は設計書を作成、廃止時は設計書から該当セクションを削除

## 検証
- 変更完了後に再度 grep して残存参照がゼロであることを確認する
- テストを実行して既存機能の破壊がないことを確認する
- TypeScript: `npx tsc --noEmit` で型チェック

## コミットとプッシュ
- 実装の区切りごとにコミット＆プッシュする（最後にまとめてではなく）
- コミットメッセージは変更の「なぜ」を書く

## Rules
- 作業開始前の grep を省略しない。これが最も重要なステップ
- 「ソースコードだけ直してドキュメントは後で」にしない。同時に更新する
- 廃止した機能のコードは中途半端に残さず完全に削除する
