# マルチファイルプロジェクト作成スキル

## このスキルの目的

複数ファイルで構成されるプロジェクト（Webアプリ、ゲーム、CLI等）を新規作成する際に、
ファイル間の整合性を保ちながら効率的に実装を完遂するための手順書。

## 手順

### Step 1: 要件定義（テキストのみ、ツール不要）

ユーザーの要求を確認し、以下を明確にする:
- 何を作るか（名前、目的）
- 技術スタック（HTML+JS, Python, Node.js 等）
- 出力先ディレクトリ

不明な場合は ask_user で確認する。過度な設計書は不要。

### Step 2: ファイル一覧と依存関係の設計

todo_write で以下を定義する:
```
1. [ファイルパス]: 責務と依存関係
2. [ファイルパス]: 責務と依存関係
...
```

**依存順序を明示すること:**
- 依存される側（定数、型定義、ユーティリティ）を先に
- 依存する側（コアロジック、UI、エントリポイント）を後に

### Step 3: ファイル生成（依存順に実行）

**以下のルールを厳守:**

1. **依存される側のファイルから順に file_write する**
   - 例: constants.js → utils.js → Board.js → Game.js → main.js → index.html

2. **1つのレスポンスで独立した複数ファイルを並列に file_write する**
   - 例: constants.js と styles.css は依存関係がないので並列に書ける

3. **各ファイルを書いたら、tool_result の Exports 情報を確認する**
   - 次のファイルを書くとき、前のファイルの export/関数名を正確に参照する

4. **コードは完全に動作する状態で書く**
   - `// TODO` や未実装部分を残さない
   - import/require のパスが正しいことを確認する

5. **文字列リテラルのクォートを忘れない**
   - 特に色値(`'#ff0000'`)、キー名、URLなど

### Step 4: 整合性検証

全ファイル作成後:

1. **エントリポイントを file_read して、全ファイルへの参照パスが正しいか確認する**
   - HTML: `<script src="...">` / `<link href="...">` のパス
   - JS: `import ... from '...'` / `require('...')` のパス

2. **コアファイルを file_read して、他ファイルの関数・クラス呼び出しが正しいか確認する**
   - メソッド名、引数の数、プロパティ名の整合性

3. **問題があれば file_write で修正する**（file_edit ではなく全体書き直しが確実）

### Step 5: 完了報告

作成したファイル一覧と使用方法をユーザーに報告する。

## 注意事項

- **テキストで計画を述べるだけで終わらないこと**。考えたら即座に file_write を呼び出す
- **同じ操作を2回失敗したら別のアプローチに切り替える**
- 大量のファイルがある場合、関連するファイルを3-5個ずつのバッチで生成する
- 構文エラーが報告された場合は即座に修正してから次のファイルに進む
