# 第 3 章：セキュリティとコンプライアンス

## はじめに

生成 AI システムのセキュリティは、企業にとって最も重要な考慮事項の一つです。本章では、データ保護、認証・認可、監査、コンプライアンス対応を解説します。

---

## 3-1 データ保護対策

### データの分類

#### 1. 公開データ

**特徴**:
- 外部公開可能
- セキュリティ要件が低
- 例：一般情報、公開ドキュメント

#### 2. 内部データ

**特徴**:
- 社内限定
- 中程度のセキュリティ要件
- 例：社内マニュアル、議事録

#### 3. 機密データ

**特徴**:
- 厳格な制限
- 高いセキュリティ要件
- 例：顧客情報、財務データ

#### 4. 超機密データ

**特徴**:
- 最小限のアクセス
- 最高レベルのセキュリティ
- 例：個人情報、知的財産

### 保護対策

#### 1. 暗号化

**転送中の暗号化**:
```
- TLS 1.3 の使用
- 強力な暗号スイート
- 定期的な証明書更新
```

**保存時の暗号化**:
```
- AES-256 以上の使用
- キー管理の厳格化
- キーローテーション
```

**実装例**:
```python
from cryptography.fernet import Fernet

# キー生成
key = Fernet.generate_key()
cipher = Fernet(key)

# 暗号化
data = "機密情報"
encrypted = cipher.encrypt(data.encode())

# 復号化
decrypted = cipher.decrypt(encrypted).decode()
```

#### 2. データマスキング

**完全マスキング**:
```
名前：山田太郎 → ***
生年月日：1990-01-01 → ****-**-**
```

**部分マスキング**:
```
メールアドレス：user@example.com → u***@example.com
電話番号：03-1234-5678 → 03-****-5678
```

**実装例**:
```python
import re

def mask_email(email):
    match = re.match(r'(\w)(\w+)(@\w+\.(\w+))', email)
    if match:
        return match.group(1) + '*' * len(match.group(2)) + match.group(3)
    return email

# 結果：user@example.com → u***@example.com
```

#### 3. アクセス制御

**ロールベースアクセス制御（RBAC）**:
```
┌───────────┬─────────────────┬─────────┐
│    ロール    │     権限       │  データ   │
├───────────┼─────────────────┼─────────┤
│  管理者     │  全権限         │  全て    │
│  一般ユーザー│  読み取りのみ     │  公開     │
│  編集者     │  読み書き       │  内部     │
│  ゲスト     │  限定読み取り     │  公開     │
└───────────┴─────────────────┴─────────┘
```

**属性ベースアクセス制御（ABAC）**:
```
if user.department == "財務" and data.classification == "財務データ":
    許可
else:
    拒否
```

## 3-2 認証・認可設計

### 認証

#### 1. 多要素認証（MFA）

**組み合わせ例**:
```
1. パスワード（知識）
2. スマホ認証（所持）
3. 生体認証（生体）
```

**実装フロー**:
```
┌───────┐     ┌───────┐     ┌───────┐
│ パスワード│────▶│ MFA   │────▶│ 認証完了 │
│ 認証    │     │ 認証   │     │       │
└───────┘     └───────┘     └───────┘
```

#### 2. OAuth 2.0 / OIDC

**認証フロー**:
```
1. ユーザー → アプリ
2. アプリ → 認証サーバー
3. 認証サーバー → ユーザー（認証）
4. ユーザー → 認証サーバー（承認）
5. 認証サーバー → アプリ（アクセストークン）
6. アプリ → API（トークン使用）
```

**実装例**:
```python
from authlib.integrations.flask_client import OAuth

oauth = OAuth(app)

google = oauth.register(
    name='google',
    client_id=CONFIG['GOOGLE_CLIENT_ID'],
    client_secret=CONFIG['GOOGLE_CLIENT_SECRET'],
    authorize_url='https://accounts.google.com/o/oauth2/auth',
    access_token_url='https://accounts.google.com/o/oauth2/token',
    userinfo_endpoint='https://openidconnect.googleapis.com/v2/userinfo'
)
```

### 認可

#### 1. トークンベース認可

**JWT トークン構造**:
```json
{
  "header": {
    "alg": "HS256",
    "typ": "JWT"
  },
  "payload": {
    "sub": "user123",
    "role": "admin",
    "exp": 1234567890
  },
  "signature": "..."
}
```

**検証ロジック**:
```python
import jwt

def verify_token(token):
    try:
        payload = jwt.decode(
            token,
            SECRET_KEY,
            algorithms=['HS256']
        )
        return True, payload
    except jwt.ExpiredSignatureError:
        return False, "トークン期限切れ"
    except jwt.InvalidTokenError:
        return False, "無効なトークン"
```

#### 2. API キー管理

**ベストプラクティス**:
```
1. 環境変数での管理
2. 定期的なローテーション
3. アクセスログの記録
4. 使用制限の設定
```

**実装例**:
```python
import os
from functools import wraps

def require_api_key(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        api_key = request.headers.get('X-API-Key')
        valid_key = os.environ.get('VALID_API_KEY')
        
        if not api_key or api_key != valid_key:
            return {'error': 'Unauthorized'}, 401
        
        return f(*args, **kwargs)
    return decorated
```

## 3-3 監査とログ管理

### ログの収集

#### 収集すべき情報

**1. アクセスログ**:
```
- ユーザー ID
- タイムスタンプ
- IP アドレス
- アクセスしたリソース
- 結果（成功/失敗）
```

**2. 操作ログ**:
```
- 操作の種類
- 変更前の値
- 変更後の値
- 操作したユーザー
```

**3. システムログ**:
```
- エラーメッセージ
- パフォーマンス指標
- リソース使用状況
```

#### ログフォーマット

**JSON フォーマット**:
```json
{
  "timestamp": "2024-01-15T10:30:00Z",
  "level": "INFO",
  "user_id": "user123",
  "action": "document_access",
  "resource": "doc-456",
  "ip": "192.168.1.100",
  "result": "success"
}
```

### ログの保存

#### 保存ポリシー

**保持期間**:
```
- アクセスログ：1 年
- 操作ログ：3 年
- システムログ：90 日
```

**保存場所**:
```
- 主要ログ：ホットストレージ（高速アクセス）
- 履歴ログ：コールドストレージ（アーカイブ）
```

#### 改ざん防止

**対策**:
```
1. 書き込み専用ストレージ
2. 改ざん検出
3. 暗号化署名
```

**実装例**:
```python
import hashlib

def log_with_signature(log_entry):
    # ハッシュ計算
    hash_value = hashlib.sha256(
        log_entry.encode()
    ).hexdigest()
    
    # 署名追加
    signed_entry = {
        **log_entry,
        'signature': hash_value
    }
    
    return signed_entry
```

### 監査の自動化

#### 異常検知

**ルールベース**:
```
- 短時間内の多数アクセス
- 通常時間帯外アクセス
- 通常場所外アクセス
- 権限外アクセス
```

**機械学習ベース**:
```
- ユーザー行動のベースライン作成
- 異常の検出
- アラート
```

#### 監査レポート

**自動生成**:
```
- 日次レポート
- 週次レポート
- 月次レポート
```

**内容**:
```
- アクセス統計
- 異常検知結果
- セキュリティイベント
- コンプライアンスステータス
```

## 3-4 コンプライアンス対応

### GDPR（EU 一般データ保護規則）

#### 主要要件

**1. 同意の管理**:
```
- 明確な同意
- 撤回可能
- 記録の保持
```

**2. データ主体の権利**:
```
- アクセス権
- 訂正権
- 削除権（忘れられる権利）
- 携帯権
```

**3. データ保護影響評価（DPIA）**:
```
- リスク評価
- 対策の実装
- 定期的な見直し
```

#### 実装のポイント

**同意管理**:
```python
class ConsentManager:
    def record_consent(self, user_id, purpose, timestamp):
        consent = {
            'user_id': user_id,
            'purpose': purpose,
            'timestamp': timestamp,
            'status': 'granted'
        }
        # 保存
        return consent
    
    def revoke_consent(self, user_id):
        # 同意の撤回
        # 関連データの削除
        pass
```

**データ削除**:
```python
def delete_user_data(user_id):
    # 全てのシステムから削除
    # バックアップも含む
    # 削除の記録
    pass
```

### 個人情報保護法（日本）

#### 主要要件

**1. 利用目的の特定**:
```
- 利用目的の明示
- 目的外利用の制限
```

**2. 取得の制限**:
```
- 適正な手段での取得
- 不正な手段の禁止
```

**3. 安全管理措置**:
```
- 組織的対策
- 物理的対策
- 技術的対策
```

### SOC 2

#### 5 つの原則

**1. 機密性**:
```
- アクセス制御
- 暗号化
```

**2. 可用性**:
```
- バックアップ
- 災害復旧
```

**3. 完全性**:
```
- 変更管理
- データ整合性
```

**4. 処理の機密性**:
```
- 処理の制限
- 監査
```

**5. プライバシー**:
```
- 収集の制限
- 利用の制限
```
