# 第 4 章：システムアーキテクチャ

## はじめに

堅牢な生成 AI システムを構築するには、適切なアーキテクチャ設計が不可欠です。本章では、マイクロサービス設計、API ゲートウェイ、キャッシュ戦略、レジリエンス設計を解説します。

## 4-1 マイクロサービス設計

### マイクロサービスアーキテクチャ

#### モノリシック vs マイクロサービス

**モノリシック**:
```
┌──────────────────────┐
│   単一アプリケーション    │
│  ┌────┬────┬────┐   │
│  │UI  │  論理  │ DB │   │
│  └────┴────┴────┘   │
└──────────────────────┘
```

**マイクロサービス**:
```
┌───┐  ┌───┐  ┌───┐
│UI │─▶│API │─▶│LLM│
└───┘  └───┘  └───┘
           │     │
           ▼     ▼
        ┌───┐ ┌───┐
        │DB │ │Cache│
        └───┘ └───┘
```

#### マイクロサービスのメリット

**1. 独立性**:
```
- 個別の開発
- 個別のデプロイ
- 個別のスケーリング
```

**2. 技術スタックの柔軟性**:
```
- サービスごとに技術選択
- 最適化の容易さ
- レガシーとの共存
```

**3. 障害の隔離**:
```
- 単一障害点の排除
- 障害の局所化
- システム全体の可用性向上
```

### サービス間通信

#### 同期通信（REST/gRPC）

**REST API**:
```python
import requests

def call_llm_service(prompt):
    response = requests.post(
        'http://llm-service/api/completions',
        json={'prompt': prompt}
    )
    return response.json()
```

**gRPC**:
```protobuf
service LLMService {
  rpc GenerateCompletion(CompletionRequest) returns (CompletionResponse);
}

message CompletionRequest {
  string prompt = 1;
  int32 max_tokens = 2;
}

message CompletionResponse {
  string completion = 1;
  int32 token_count = 2;
}
```

#### 非同期通信（メッセージキュー）

**RabbitMQ 例**:
```python
import pika

connection = pika.BlockingConnection(
    pika.ConnectionParameters('rabbitmq')
```

## 4-3 キャッシュ戦略

### キャッシュの重要性

生成 AI API は遅延とコストの両面で課題があります。

#### キャッシュのメリット

**1. 遅延の削減**:
```
キャッシュ Hit: 10ms
キャッシュ Miss: 500ms
```

**2. コスト削減**:
```
キャッシュ Hit: $0
キャッシュ Miss: $0.002/1K tokens
```

**3. スループット向上**:
```
- API リクエスト数の削減
- サービス負荷の軽減
```

### キャッシュ戦略

#### 1. レスポンスキャッシュ

**ハッシュキーの生成**:
```python
import hashlib

def generate_cache_key(prompt, params):
    data = f"{prompt}:{params}"
    return hashlib.md5(data.encode()).hexdigest()
```

**Redis 実装**:
```python
import redis
import json

cache = redis.Redis(host='localhost', port=6379)

def get_completion(prompt, params):
    cache_key = generate_cache_key(prompt, params)
    
    # キャッシュヒット
    cached = cache.get(cache_key)
    if cached:
        return json.loads(cached)
    
    # API 呼び出し
    result = call_llm_api(prompt, params)
    
    # キャッシュ保存（TTL: 1 時間）
    cache.setex(cache_key, 3600, json.dumps(result))
    
    return result
```

#### 2. セグメントキャッシュ

**長回答のキャッシュ**:
```
┌──────────────────────────┐
│   長回答                  │
├──────┬──────┬──────┬────┤
│ セグ 1 │ セグ 2 │ セグ 3 │ セグ 4 │
└──────┴──────┴──────┴────┘
  ↑        ↑
キャッシュ    キャッシュ
```

**実装**:
```python
def cache_segments(response, segment_size=100):
    segments = [response[i:i+segment_size] 
                for i in range(0, len(response), segment_size)]
    
    for i, segment in enumerate(segments):
        cache_key = f"segment:{hash(segment)}"
        cache.setex(cache_key, 3600, segment)
```

#### 3. スマートキャッシュ

**動的 TTL**:
```python
def calculate_ttl(response_type, age):
    if response_type == "fact":
        return 86400  # 1 日
    elif response_type == "opinion":
        return 3600  # 1 時間
    else:
        return 300  # 5 分
```

**優先度ベース**:
```python
class PriorityCache:
    def __init__(self):
        self.cache = {}
        self.priorities = {}
    
    def set(self, key, value, priority):
        self.cache[key] = value
        self.priorities[key] = priority
    
    def evict(self):
        # 最優先度のエントリを削除
        min_key = min(self.priorities, key=self.priorities.get)
        del self.cache[min_key]
        del self.priorities[min_key]
```

### キャッシュ無効化戦略

**TTL ベース**:
```
- 固定時間後削除
- 単純だが効果的
```

**書き込み時無効化**:
```
- データ更新時にキャッシュ削除
- 一貫性確保
```

**レイシ評価**:
```
- キャッシュが切れても古い値を返す
- バックグラウンドで更新
```

## 4-4 レジリエンス設計

### レジリエンスパターン

#### 1. リトライ

**指数バックオフ**:
```python
import time
import random

def retry_with_backoff(func, max_retries=3):
    for i in range(max_retries):
        try:
            return func()
        except Exception as e:
            if i == max_retries - 1:
                raise
            
            wait_time = (2 ** i) + random.uniform(0, 1)
            time.sleep(wait_time)
```

**実装例**:
```python
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=30)
)
def call_llm_api(prompt):
    # API 呼び出し
    pass
```

#### 2. サーキットブレーカー

**状態遷移**:
```
Closed ──[エラー閾値]──▶ Open ──[待機時間]──▶ Half-Open ──[成功]──▶ Closed
```

**実装例**:
```python
from pybreaker import CircuitBreaker

llm_breaker = CircuitBreaker(
    fail_max=5,
    reset_timeout=30
)

@llm_breaker
def call_llm_service(prompt):
    return requests.post('http://llm-service/api', json={'prompt': prompt})
```

#### 3. フェイルオーバー

**アクティブ - パッシブ**:
```
┌─────────┐
│ Primary │───▶ 全トラフィック
└─────────┘
     │
     │ (障害)
     ▼
┌─────────┐
│ Backup  │───▶ トラフィック受け渡し
└─────────┘
```

**アクティブ - アクティブ**:
```
┌─────────┐     ┌─────────┐
│ Region A│     │ Region B│
│  50%    │     │  50%    │
└─────────┘     └─────────┘
```

#### 4. フォールバック

**多段階フォールバック**:
```
1. 主要 LLM
   ↓ (失敗)
2. 次要 LLM
   ↓ (失敗)
3. ルールベース応答
   ↓ (失敗)
4. エラーメッセージ
```

**実装例**:
```python
def get_completion_with_fallback(prompt):
    # 1. 主要 LLM
    try:
        return primary_llm(prompt)
    except:
        pass
    
    # 2. 次要 LLM
    try:
        return secondary_llm(prompt)
    except:
        pass
    
    # 3. フォールバック
    return "現在、応答生成に問題があります。"
```
