# 第 1 章：生成 AI 技術の基礎理解

## はじめに

生成 AI を導入する際、まずは技術的な基礎を理解することが重要です。本章では、LLM（大規模言語モデル）の仕組み、API 連携の基本概念、主要プロバイダーの比較を解説します。

---

## 1-1 LLM の仕組みと種類

### LLM とは

LLM（Large Language Model）は、大量のテキストデータから学習した人工知能モデルです。

#### 主要な特徴

```
- 自然言語の理解と生成
- 文脈の把握
- 推論能力
- コード生成
- 多言語対応
```

### トランスフォーマーアーキテクチャ

現代の LLM は、トランスフォーマーアーキテクチャに基づいています。

#### 基本概念

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   エンコーダ   │  →  │   アテンション  │  →  │   デコーダ   │
│  (入力処理)   │     │   (文脈把握)   │     │  (出力生成)   │
└──────────────┘     └──────────────┘     └──────────────┘
```

#### エンコーダ・デコーダの説明

**エンコーダ**:
- 入力テキストを数値ベクトルに変換
- 各単語の文脈を考慮

**アテンション機構**:
- 単語間の関係性を把握
- 重要な部分に集中

**デコーダ**:
- ベクトルをテキストに変換
- 逐次的に単語を生成

### LLM の種類

#### 1. 汎用モデル

**特徴**:
- 一般的なタスクに最適化
- 広範な知識
- 多様な用途

**例**: GPT-4, Claude, Gemini

#### 2. 専門モデル

**特徴**:
- 特定のドメインに特化
- 高い精度
- 限定的な用途

**例**:
- コード専用：CodeLlama
- 医療専用：Med-PaLM
- 法律専用：Lawyer LLM

#### 3. オープンソースモデル

**特徴**:
- 無料で利用可能
- カスタマイズ可能
- ローカル実行可能

**例**: Llama 2, Mistral, Falcon

## 1-2 API 連携の基本概念

### RESTful API

LLM プロバイダーの多くは、RESTful API を提供しています。

#### 基本的なリクエスト構造

```json
{
  "model": "gpt-4",
  "messages": [
    {"role": "system", "content": "あなたはアシスタントです。"},
    {"role": "user", "content": "こんにちは"}
  ],
  "temperature": 0.7,
  "max_tokens": 100
}
```

#### 基本的なレスポンス構造

```json
{
  "id": "chatcmpl-xxx",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "こんにちは！何かお手伝いしましょうか？"
      }
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 15,
    "total_tokens": 25
  }
}
```

### 主要パラメータ

#### temperature
- 出力のランダム性を制御
- 0: 決定論的、1: ランダム
- 推奨値：0.7（バランス）

```python
# 低 temperature（正確性重視）
temperature = 0.2  # 事実ベースのタスク

# 高 temperature（創造性重視）
temperature = 0.9  # 創作タスク
```

#### max_tokens
- 生成するトークンの最大数
- コストと出力長のバランス

#### top_p
- 確率の累積閾値
- nucleus sampling

#### frequency_penalty
- 繰り返しを抑制
- 多様性を向上

### 認証方法

#### API キー認証

```python
import requests

headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.post(
    "https://api.provider.com/v1/chat/completions",
    headers=headers,
    json=payload
)
```

#### ベストプラクティス

1. **API キーの管理**
   - 環境変数で管理
   - コードにハードコードしない
   - 定期的なローテーション

2. ** rate limiting の考慮**
   - リクエスト制限を把握
   - 自動リトライ実装
   - キューイングの実装

## 1-3 主要プロバイダー比較

### 比較項目

| 項目 | OpenAI | Anthropic | Google | ローカル |
|------|--------|-----------|--------|----------|
| 主要モデル | GPT-4 | Claude | Gemini | Llama 2 |
| 価格 | 高 | 中〜高 | 中〜高 | 無料 |
| 遅延 | 低 | 中 | 低 | 高 |
| データプライバシー | クラウド | クラウド | クラウド | オンプレミス |
| カスタマイズ | 制限 | 制限 | 制限 | 完全 |

### OpenAI（GPT-4）

**特徴**:
- 業界標準
- 最も広範な機能
- 高い精度

**価格**（目安）:
- GPT-4: $0.03/1K トークン（入力）
- GPT-4: $0.06/1K トークン（出力）

**メリット**:
- 安定性が高い
- ドキュメントが充実
- コミュニティが大きい

**デメリット**:
- 高コスト
- データがクラウドに送信される
- カスタマイズ制限

### Anthropic（Claude）

**特徴**:
- セキュリティ重視
- 長いコンテキスト
- 倫理的配慮

**価格**（目安）:
- Claude 2: $0.008/1K トークン（入力）
- Claude 2: $0.024/1K トークン（出力）

**メリット**:
- 安全性が高い
- 長いコンテキストウィンドウ
- コストパフォーマンス良好

**デメリット**:
- 機能制限がある
- 利用制限が厳しい
- コミュニティが小さい

### Google（Gemini）

**特徴**:
- Google エコシステム統合
- 多様なモデルサイズ
- 無料枠あり

**価格**（目安）:
- Gemini Pro: $0.0005/1K トークン（入力）
- Gemini Pro: $0.0015/1K トークン（出力）

**メリット**:
- コストが安い
- Google 製品との統合
- 無料枠が利用可能

**デメリット**:
- 精度が不安定
- ドキュメントが不十分
- 機能が制限される

### ローカル LLM（Llama 2 など）

**特徴**:
- 完全な制御
- データプライバシー
- 無料

**価格**:
- ソフトウェア：無料
- インフラ：自己負担

**メリット**:
- データが社内に残る
- 完全なカスタマイズ
- 利用制限なし

**デメリット**:
- ハードウェアコスト
- 運用コスト
- 精度が低い場合がある

## 1-4 モデル選定のガイドライン

### 選定フレームワーク

#### ステップ 1: 要件の明確化

**質問リスト**:


### 具体的なユースケース別の推奨

#### 顧客対応チャットボット
- **推奨**: OpenAI GPT-4
- **理由**: 高い精度、安定性

#### ドキュメント分析
- **推奨**: Anthropic Claude
- **理由**: 長いコンテキスト、正確性

#### コード生成
- **推奨**: ローカル CodeLlama
- **理由**: コードの機密性

#### 内部検索
- **推奨**: Google Gemini
- **理由**: コスト効率、統合性

#### 機密データ処理
- **推奨**: ローカル Llama 2
- **理由**: データプライバシー
