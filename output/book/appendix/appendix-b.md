# 付録 B：FAQ（よくある質問）

## 導入に関する FAQ

### Q1: どの部門から始めるべきですか？

**A:** 以下の基準で部門を選定してください。

**選定基準：**
1. **ビジネス価値が明確**：解決する課題が明確で、成果が測定可能
2. **抵抗が少なく**：部門内の理解が得られやすい
3. **Quick Win が期待できる**：短期間で成果が見込める
4. **リソースが確保できる**：十分な時間と予算がある
5. **部門リーダーが協力的**：変革へのコミットメントがある

**推奨部門：**
- 営業部門（文書作成、顧客対応）
- カスタマーサポート（応答時間削減）
- 開発部門（コード生成、レビュー）
- 総務部門（議事録作成、資料作成）

**避けるべき部門：**
- 変革への抵抗が強い部門
- 既存業務で手一杯の部門
- セキュリティリスクが高い部門
- 成果が測定しにくい部門

---

### Q2: どれくらい予算が必要です？

**A:** 企業の規模と導入範囲によりますが、以下の目安を参考にしてください。

**パイロットプロジェクト：**
- 小規模（5-10 名）：100-300 万円
- 中規模（10-30 名）：300-500 万円
- 大規模（30 名以上）：500-1000 万円

**予算の内訳：**
- ソフトウェアライセンス：30-40%
- 実装・統合：20-30%
- トレーニング：15-25%
- コンサルティング：10-20%
- 運用・維持：10-15%

**全社展開：**
- 従業員 100 名：1000-3000 万円
- 従業員 500 名：3000-10000 万円
- 従業員 1000 名：10000-30000 万円

---

### Q3: どれくらい時間がかかりますか？

**A:** 以下の目安を参考にしてください。

**パイロットプロジェクト：**
- 計画：1-2 ヶ月
- 導入：3-6 ヶ月
- 評価：1-2 ヶ月
- **合計：5-10 ヶ月**

**全社展開：**
- フェーズ 1（一部部門）：6-12 ヶ月
- フェーズ 2（拡大）：6-12 ヶ月
- フェーズ 3（定着）：6-12 ヶ月
- **合計：18-36 ヶ月**

**成熟：**
- 継続的改善：12 ヶ月以上
- 文化変革の定着：24 ヶ月以上

### Q4: 失敗したらどうしますか？

**A:** 失敗は学習の機会です。以下の手順で対応してください。

**対応手順：**
1. **原因の分析**：何が失敗したか特定
2. **影響の評価**：組織への影響を評価
3. **改善策の策定**：再発防止策を策定
4. **学習の共有**：教訓を組織全体で共有
5. **再起動**：改善策を反映して再起動

**失敗の再定義：**
- 「失敗」→「学習の機会」
- 「無駄」→「投資」
- 「問題」→「改善点」

---

### Q5: どのツールを選べばいいですか？

**A:** 以下の基準でツールを選定してください。

**選定基準：**
1. **ビジネス要件**：解決する課題に合致しているか
2. **セキュリティ**：データセキュリティが確保されているか
3. **統合性**：既存システムと統合可能か
4. **拡張性**：将来的な拡張が可能か
5. **コスト**：予算内で導入可能か
6. **サポート**：十分なサポートが得られるか

**推奨アプローチ：**
- 複数ベンダーの評価
- パイロットでのテスト
- 既存ユーザーへの調査
- ベンダーとの交渉

## 抵抗勢力に関する FAQ

### Q6: 抵抗勢力をどう対応すればいいですか？

**A:** 抵抗勢力のタイプ別に対応策があります。

**恐れる人々：**
- 恐怖を否定せず、共感を示す
- 「AI による代替」ではなく「AI による拡張」を強調
- キャリアパスの再設計を示す

**懐疑論者：**
- 具体的なデータを提示
- パイロットプロジェクトで実証
- 第三者の評価や事例を示す

**既得権益層：**
- 既存の成功を認め、尊重
- 変化が「奪う」のではなく「強化する」ことを示す
- 彼らをリーダーシップの役割に巻き込む

**忙しい経営層：**
- 短期的な ROI を示す
- 既存の優先事項との整合性を示す
- 最小限のリソースで始められることを示す

**技術アレルギー層：**
- 技術的な側面を最小限にする
- 直感的な使い方を強調
- 継続的なサポートを提供

## 効果測定に関する FAQ

### Q12: 効果はどのように測定すればいいですか？

**A:** 以下の指標で効果測定してください。

**定量的指標：**
- 採用率（アクティブユーザー数）
- 使用頻度
- 業務効率化の定量化
- 満足度調査
- ROI の計算

**定性的指標：**
- ユーザー満足度
- ユーザー体験
- 組織文化への影響
- 学習と成長

**測定頻度：**
- 日常的指標：週次
- パフォーマンス指標：月次
- ビジネス成果：四半期

---

### Q13: ROI はどのように計算すればいいですか？

**A:** 以下の式で ROI を計算してください。

**ROI の計算式：**
```
ROI = (利益 - 投資) / 投資 × 100
```

**利益の項目：**
- 時間削減によるコスト削減
- 生産性向上による収益増加
- 品質向上によるコスト削減
- 顧客満足度向上による収益増加

**投資の項目：**
- ソフトウェアライセンス
- 実装・統合
- トレーニング
- コンサルティング
- 運用・維持

**回収期間の計算：**
```
回収期間 = 投資 / 月次効果
```

## その他の FAQ

### Q16: 外部コンサルタントは必要ですか？

**A:** 状況によりますが、以下の場合は推奨します。

**外部コンサルタントが推奨される場合：**
- 社内知識が不足している
- 時間的制約がある
- 客観的な視点が必要
- ベストプラクティスの導入

**社内で対応可能な場合：**
- 社内知識が豊富
- 十分な時間がある
- 既存のネットワークがある
- コスト削減が必要

---

### Q17: どのタイミングで導入すべきですか？

**A:** 以下のサインが見られたら導入を検討してください。

**導入のタイミング：**
- 業績の停滞または低下
- 顧客満足度の低下
- 人材の流出率の上昇
- イノベーションの欠如
- 競合の導入
- 顧客の期待変化

**避けるべきタイミング：**
- 経営危機時
- 大規模な再編時
- 予算制約時
- 人材不足時

---

### Q18: 導入の優先順位はどうつけますか？

**A:** 以下の基準で優先順位を付けてください。

**優先順位の基準：**
1. **ビジネス価値**：高いビジネス価値
2. **実現可能性**：高い実現可能性
3. **リスク**：低いリスク
4. **リソース**：十分なリソース
5. **タイミング**：適切なタイミング

**優先順位の付け方：**
- スコアリング方式
- 影響度×実現可能性マトリクス
- 緊急度×重要度マトリクス
